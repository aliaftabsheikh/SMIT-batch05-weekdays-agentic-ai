# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

This is a **teaching repository** for a year-long "Certified Agentic AI Engineer" course (see `README.md` for the full curriculum). It is **not** a single application — it is a collection of per-class exercises and demonstrations. Expect small, self-contained scripts and pages rather than a cohesive codebase, and expect deliberately incomplete or commented-out code (classes evolve a single file live during a session).

Two very different bodies of work live side by side; identify which one a task belongs to before acting:

1. **Class exercises** — `class-1/` … `class-21/`, `prompt-engineering/`. Mostly standalone Python (`app.py`) teaching one concept each, plus some static HTML. No shared package, no cross-file imports beyond a local module (e.g. `class-10/calc.py`). Some folders hold teaching guides rather than code — e.g. `class-20/claude-code-landing-page-guide.md` is a 10-step, copy-paste prompt walkthrough for building a landing page with Claude Code; treat such guides as the lesson content, not as specs to implement.
2. **Spec-Driven Development (SpecKit) scaffolding** — `spec-driven-development/`, `specs/`, `history/`, `.specify/`, `AGENTS.md`. A formal workflow layer used when building features via specs. This has strict process rules (below).

## Running things

There is no build system, test suite, linter, or dependency manifest at the repo root. Each artifact runs on its own:

- **Python class files:** `python class-N/app.py` (Python 3.x; files use `python 3.13` bytecode cache in `class-10/__pycache__`). Most are throwaway demos; many lines are intentionally commented out.
- **Static pages** (`class-1/index.html` + `styles.css`, `prompt-engineering/class-3/index.html`): open the HTML file directly in a browser. No server, no build, zero dependencies.
- **Do not** add a package manager, bundler, framework, or CI to a class exercise. Keep changes minimal and local to the one file being taught.

## Spec-Driven Development workflow (when working under `specs/` / SpecKit)

The `spec-driven-development/class-1/` tree contains two parallel agent setups — `claudecode/` (Claude Code, commands under `.claude/commands/sp.*.md`) and `opencode/` (`.opencode/command/`). They implement the same SpecKit-Plus flow. Read `spec-driven-development/class-1/claudecode/CLAUDE.md` for the full agent contract before doing SDD work. The pipeline of slash commands:

`/sp.constitution` → `/sp.specify` → `/sp.clarify` → `/sp.plan` → `/sp.tasks` → `/sp.implement`, plus `/sp.adr`, `/sp.analyze`, `/sp.checklist`, `/sp.git.commit_pr`, `/sp.phr`.

Two hard rules from that workflow, which the human depends on:

- **PHRs (Prompt History Records):** every user request gets a record under `history/prompts/`, routed by stage — `constitution/`, `<feature-name>/` (feature work), or `general/`. Use the template at `.specify/templates/phr-template.prompt.md`. Preserve the user's prompt verbatim.
- **ADRs (Architecture Decision Records):** never auto-create. When a decision is architecturally significant (impact + alternatives + cross-cutting scope), *suggest* `/sp.adr <title>` and wait for consent.

Feature artifacts live at `specs/<feature>/`: `spec.md`, `plan.md`, `tasks.md`, `research.md`, `data-model.md`, `quickstart.md`, `contracts/`, `checklists/`. The active example is `specs/001-landing-page/` (a pure HTML+CSS "Velocity" landing page, branch `001-landing-page`). Its governing principles are in `spec-driven-development/class-1/claudecode/.specify/memory/constitution.md`: spec-first + traceable, semantic/accessible HTML, design-token-driven responsive CSS, progressive enhancement, smallest-viable-change with zero build bloat.

`AGENTS.md` at the repo root is auto-generated by the SpecKit `update-agent-context` script — do not hand-edit it as primary documentation; it is regenerated from feature plans.

## Conventions

- **Match the surrounding class's style.** These files are read by students; clarity beats cleverness. Keep the existing pattern of commented-out alternatives when editing a teaching file — those comments are the lesson.
- **Windows environment.** Primary shell is PowerShell; a Bash tool is also available. SpecKit ships both `.specify/scripts/bash/*.sh` and `.specify/scripts/powershell/*.ps1` — pick the one matching the shell in use.
- **Note:** `claude-code/class-1/CLAUDE.md` is an unrelated Snake-game template, not guidance for this repo. Ignore it unless a task is specifically about that exercise.
